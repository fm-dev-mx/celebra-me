## 1. Executive summary

The week's history is healthy where the gates enforce it and drifts where only people enforce it.

- **Clean:** every commit is a Conventional Commit with a scope; no `wip`, `fixup!`, plan codes or
  over-long headers; no secrets, environment files, backups or build output entered the history;
  `main` received only release merges; every pull request merged with a merge commit.
- **Drift (no rewrite needed):** 27 remote and 38 local task branches stay alive after merge; four
  agent worktrees outlived their sessions; two release merges on `main` have no tag
  (`v0.21.0-beta.1`, `v0.28.1-beta.1`) and three old version tags never reached `origin`; there are
  no GitHub Releases; 13 of the 87 commits written after the scope list was enforced (2026-10-14)
  still use an unlisted scope.
- **Policy gaps:** task branches named `docs/*` and `chore/*` are in common use but the policy lists
  only `feat/*`, `fix/*` and `candidate/*`; 24 of 71 task merges went through a GitHub pull request
  although the policy describes a local `--no-ff` merge; GitHub allowed squash and rebase merges and
  kept head branches after merge (fixed during the audit, see
  [5.6](#56-github-repository-settings)).

No history was rewritten and no ref on `origin` was changed by this audit. The owner approved the
GitHub merge settings in 5.6; every other deletion and tag push is listed in
[section 5](#5-actions-pending-owner-approval).

### 3.3 Author identity

All locally written commits use one personal address from the local Git configuration. The noreply
address appears only on merges made with GitHub's web merge button, because the account keeps its
email private. Recommendation: keep the local identity for every authored commit and accept the
noreply address for web merges, or add the personal address to the account's "commit email" setting
so web merges use it too. Both are account settings; nothing in the repository needs to change.
